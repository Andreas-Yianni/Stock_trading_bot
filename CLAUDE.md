# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Trading *analysis* bot for stocks and crypto: technical indicators + free news sentiment → score, bias and an indicative trade plan (entry / SL / TP / position size). It **never executes real-money trades** — keep it that way. The only execution path is `tradebot/broker.py`: automated **Alpaca PAPER** trading, opt-in (user decision 2026-10-19, `broker.auto_trade` / `/auto on`), hard-wired to `paper-api.alpaca.markets` and refusing non-paper accounts (key `PK…`, account `PA…`) — never add a live endpoint. The user is a Greek-speaking beginner trader; all user-facing text (reports, Telegram messages, dashboard labels, notes) is in **Greek**, code identifiers/comments in English or Greek as in surrounding code. Every report ends with `DISCLAIMER` from `tradebot/config.py`.

`ΠΟΥ_ΕΜΕΙΝΑΜΕ.md` is the user-facing "where we left off" status (Greek): read it first when asked to continue, and update it at the end of a work session. `ΟΔΗΓΟΣ_ΕΝΤΟΛΩΝ.md` is the user's Telegram command guide — keep it in sync when commands change.

`PLAN.md` holds the roadmap (Phase 2: Claude API analysis via a new `tradebot/ai.py`, Phase 3: X/Reddit/CryptoPanic, Phase 4: backtesting). Update it when a phase item is implemented.

## Commands

Windows, Python 3.14, venv at `.venv`. Use `PYTHONIOENCODING=utf-8` when running from Bash (Greek output).

```bash
./.venv/Scripts/pip install -r requirements.txt
./.venv/Scripts/python cli.py BTC            # analysis, default timeframe from config.yaml
./.venv/Scripts/python cli.py AAPL 1d --no-news
./.venv/Scripts/python cli.py --review       # evaluate paper-trading journal
./.venv/Scripts/python cli.py BTC 4h --backtest [--days N]   # historical backtest (no journal writes)
./.venv/Scripts/python cli.py all 4h --backtest              # whole watchlist (several minutes)
./.venv/Scripts/python cli.py --selfcheck    # self-check: current rules vs candidates vs SPY (watchlist, ~3 min)
./.venv/Scripts/python research/honest_test.py   # point-in-time S&P 500 test of the rules (~10 min; first run ~45)
./.venv/Scripts/streamlit run dashboard.py   # http://localhost:8501
docker compose up -d --build                 # bot + dashboard in Docker (never alongside start_bot.bat)
./.venv/Scripts/python telegram_bot.py       # needs TELEGRAM_BOT_TOKEN in .env
```

There is no test suite or linter. Verify changes by running `cli.py` against a real crypto and a real stock symbol (network required), and smoke-test the dashboard headlessly with `streamlit.testing.v1.AppTest.from_file("dashboard.py").run()` and checking `at.exception`. Note: `cli.py` and the dashboard record signals into `data/journal.db` — delete test rows/the DB after testing.

## Architecture

Pipeline lives in `tradebot/`; the three entry points (`cli.py`, `dashboard.py`, `telegram_bot.py`) are thin UIs over `engine.analyze()`.

- `market.py` — `resolve(raw)` turns user input ("BTC", "btc/usdt", "AAPL") into an `Asset` (crypto vs stock decided by `KNOWN_CRYPTO`). `fetch_ohlcv` uses ccxt (exchange from config) for crypto, **falling back to yfinance `XXX-USD`** on any error; stocks use yfinance. Yahoo has no 4h interval, so 4h is resampled from 1h. `HIGHER_TF` maps each timeframe to the one used for trend confirmation. **Yahoo intraday (1h/15m) prices are NOT dividend-adjusted, daily ones are** (JPM −6%, PFE −20% two years back) — never mix them without `backtest._match_daily`. Likewise stored live prices (entry, SL) must be compared with UNADJUSTED daily candles: `fetch_ohlcv(..., adjusted=False)` is used by `journal.replay` and `portfolio.stop_steps` (after an ex-dividend date the adjusted history shifts down and would fake a stop hit). `with market.history_cache():` memoizes `fetch_history` (used by `selfcheck`).
- `indicators.add_all(df)` — adds all indicator columns (ema20/50/200, rsi, macd*, bb_*, atr, adx/plus_di/minus_di, vol_avg20) implemented in pure pandas (no TA library — keep it that way, Python 3.14 compatibility). Downstream code accesses these by column name.
- `levels.find_levels` — swing-pivot S/R clustered within 0.5·ATR; returns nearest 3 supports/resistances as `(price, touches)`.
- `news.py` — RSS (Google News query + Yahoo ticker feed for stocks; CoinDesk/Cointelegraph/Decrypt for crypto). General feeds and Yahoo are keyword-filtered by symbol/name. Sentiment = VADER on titles with a custom `FINANCE_LEXICON`; `news_score` is recency-weighted. `fear_greed()` from alternative.me (crypto only). `market_news()` = general macro headlines (CNBC, MarketWatch, Google News) — **display only, deliberately not a Factor**: VADER misreads macro headlines badly.
- `events.py` — USD high-impact economic calendar (Forex Factory `ff_calendar_thisweek.json`, current week only) + stock earnings dates (yfinance `calendar`). Forex Factory **blocks clients that fetch more than once per hour**: the JSON is persisted to `data/ff_calendar.json` and shared by all processes — don't bypass it. `risk_warnings()` flags events <24h away (earnings <72h). `Analysis.events` / `Analysis.market_news` are filled when `with_news`; the Telegram bot runs `event_alerts` every 15 min (≈1h before macro events, day before earnings of watchlist stocks). `cache.py` = tiny in-memory TTL cache.
- `engine.py` — the core. Builds a list of `Factor(name, score∈[-1,1], weight, note)`; total `score = 100·Σ(score·weight)/Σweight`. Bias is LONG/SHORT when `|score| ≥ analysis.min_score_for_signal`. `_build_plan` is side-symmetric via `sign`: SL behind the nearest S/R that is 1–3 ATR away (else 1.5 ATR), size from `risk_per_trade_pct`, capped by `max_position_pct`. Exits by `analysis.exit_mode`: **`trend` (default since 2026-10-17)** = no take profit, `tp1/tp2 = None`, `plan.trend_atr = analysis.trend_atr` (6): stop = max(initial SL, highest high since entry − 6·ATR), updated at each candle close, never lowered (`journal.trend_stop`); `fixed` = TP1 `min_reward_risk`·R (half) + breakeven, TP2 3R, 30-day expiry; `trailing` = TP1 half then trail (legacy). Every UI must handle `tp1 is None`. To add a new signal source (e.g. the planned AI factor), append a `Factor` — reports, chart and dashboard pick it up automatically.
- `ai.py` — AI opinion with **Google Gemini free tier** (user decision 2026-10-22: free only, so not the Claude API) via plain `requests`, structured JSON output. Sees exactly the analysis' symbol news + market news (numbered), factors, levels, plan, events; returns score −1..1, confidence, summary, `action` (what it would do vs the rules), per-news effect/why, risks. `engine.add_ai` appends `Factor("AI (Gemini)")` with weight `ai.weight` (**default 0 = observation only**: score, bias and plan unchanged; >0 recomputes them). It cannot be backtested, so every new opinion goes to `data/ai_log.jsonl` to be judged against later prices before any weight is given. Autoscan/Alpaca trades never use it. Free-tier guards: cache per symbol + same headlines (`data/ai_cache.json`, `cache_hours` 12), `MIN_GAP` 7 s between calls, `ai.models` tried in order on 429/5xx/timeout (`gemini-3.5-flash` then `gemini-flash-lite-latest`; `gemini-flash-latest` gave 503 on 2026-10-22). No key or `ai.enabled: false` → no AI, analysis unchanged. `report.ai_lines` (short, in every analysis; the AI factor is not repeated in «Τι βλέπω») / `report.ai_html` (`/ai SYMBOL`: every headline it read, split with `report.split_message` for Telegram's 4096 limit), dashboard section + expander.
- `backtest.py` — replays history bar by bar with **the same** `engine._trend_factors` / `engine.combine` / `engine._build_plan` and `journal.simulate` (shared with `evaluate_open`), so rule changes in the engine are backtested automatically. No lookahead: each bar sees only `df.iloc[:i+1]` and HTF candles already closed. **Like the live bot: a trade only on a FRESH signal (bias differs from the previous bar) while flat, filled at the NEXT bar's open** (skipped if it opens beyond the SL), with the plan's SL/qty — R is in units of the plan's risk (`Trade.risk_unit`). Fixed-target exits are resolved on finer candles (`FINE_TF`, 1h inside 1d/4h; for stocks on 1d rescaled to the dividend-adjusted daily basis by `_match_daily`); trend exits use the timeframe's own candles (only a stop, needs `atr`). The open trade's current trailing stop/R is in `Result.open_trade`. `portfolio(results, balance, risk%, max_pos%)` = ONE cash account (no margin, daily mark-to-market, best score first) → CAGR / max drawdown — the honest metric to compare with buy & hold. Includes historical Fear & Greed for crypto, no news. Trades are split old (first 2/3) / new (last 1/3) — judge rule changes on the new part too, to avoid overfitting. `run_many` + `report.backtest_many_html` for the watchlist. One position at a time per symbol; fees from `config.yaml` `backtest.fee_pct`. History via `market.fetch_history` (paginated ccxt, yfinance capped at ~730d for intraday).
- `patterns.py` — causal pattern detectors (`pat_*` columns: market structure, breakout, engulfing, pin bar, RSI divergence, BB squeeze, double top/bottom, pullback). Pivots are only "known" `PIVOT_K` bars later, so no lookahead (verified by recomputing on truncated data). **Not used in the score**: the study found no reliable edge.
- `research.py` — factor/pattern study: `python -m tradebot.research 4h` measures, over 20 symbols (`CRYPTO` + `STOCKS`), the drift-adjusted forward move in ATR after each signal, with an overlap-adjusted t-score and old/new split. Engine weights/rules in `_trend_factors` are based on it (RSI>70 = bullish momentum, RSI 50–70 neutral, ADX<20 trend = 0, only green volume spikes count, HTF weight 1). Change scoring only when a study + 20-symbol backtest on 4h/1d supports it, especially on the "new" third of the data. `backtest.run(..., overrides={...})` tests `analysis` config variants without touching `config.yaml`.
- **Stocks focus (user decision 2026-10-17):** watchlist = US stocks, everything on 1d, `analysis.long_only: true` (`engine.trend_filter` turns SHORT into NEUTRAL; `report.bias_text` shows "μην αγοράσεις"). The Telegram bot scans 1d once a day (`run_daily` Tue–Sat at `alerts.daily_scan_utc`, last biases in `data/last_bias.json`), sends a morning summary and raises the trailing stops of the user's open trades.
- **Self-correction study, 2026-10-17 (read before changing rules).** (1) The earlier "+0.32R/trade, 43/44 stocks" was mostly an ARTIFACT of the dividend mismatch above (1h candles made LONGs hit TP too easily, SHORTs their SL): on consistent daily data the old rules were ≈ +0.13R on 44 large caps. (2) Honest test = `research/honest_test.py`: every S&P 500 member only while in the index, 2009–2026, entry at next open, gaps. Old fixed exits: +0.06R/trade (2009-19) / +0.01R (2020-), account CAGR ≈ 1–4% vs SPY 14.6% / 15.0%. Trend exit 6 ATR: +0.50R / +0.19R, R per member-year ×2.5 / ×7, account ≈ 8–13% / 11%. It beat the old rules in 15 of 18 years and in every universe — but **no rule tested beats SPY buy & hold** (CAGR or Sharpe). (3) "Avg R per trade" is misleading: it ignores how long capital is tied up — judge by R per year per symbol and by `backtest.portfolio` vs SPY. (4) The score adds little at entry (≈ "always LONG" per trade; thresholds 40–50 were worse); exits matter far more. (5) Cross-sectional momentum rotation looked like 30–45% CAGR on today's names but ≤ SPY point-in-time (survivorship) — any stock-selection idea must be tested point-in-time. Also no help: breakout/pullback/RSI(2) entries, SPY>SMA200 filter (hurts), low-vol ranking, fixed-ATR trail, breakeven move, partial exit at TP1.
- Tested and rejected: relative-strength ranking of stocks (2026-10-17, 44 stocks 1d long-only; 6m>SPY, top 50%/33% by 6m, top 50% by 12-1m all lowered avg R to +0.27..+0.31 vs +0.32 and cut R/year; only drawdown fell, via fewer trades) — not implemented. Also rejected the same day: SPY > SMA200/SMA100 market filter (same avg R, lower R/year, drawdown −115R vs −81R) and no entry within 3/7 days before earnings (+0.31–0.32R, same drawdown; `events` earnings warnings stay as information).
- Tested and rejected, 2026-10-22: **earnings surprise / post-earnings drift** (`research/pead.py`, same lab engine, 625 S&P 500 members point-in-time, ~27k announcements 2009-2026, Yahoo EPS estimate/actual/time, entry at the open after the reaction day). Drift exists but is tiny: +0.25..+0.31% vs SPY over 20 days after surprise ≥5% & reaction ≥+2% / reaction ≥+4%, halved after 2020 (+0.15%); negative surprise −0.15%. As entries (trend exit) every variant lost to the current rules (account 13.1% / 10.8%): surprise ≥5% 6.8/10.2%, +reaction 11.0/8.4%, reaction ≥4% 9.6/6.5%; 60-day time exit worse; none near SPY 14.6/15.0%. Not implemented.
- Tested and rejected (kept as config options, off): `analysis.trend_filter` (EMA200 side filter, ~no effect), `analysis.exit_mode: trailing` (`journal.simulate(trail=...)`; +0.015R on 4h, worse on 1d). `derivs.py` = Binance funding history; funding was not a stable predictor (sign flips old vs new), so it is not a Factor.
- `portfolio.py` — the user's OWN paper trades (table `my_trades` in `data/journal.db`), separate from `journal.py` (every bot signal). `ticket()` turns a plan into exact order fields (stocks: whole shares; crypto: 4 significant digits, rounded down; trend exit: one order, SL only; fixed: two half-size orders TP1/TP2 with the same SL, or one order if not splittable). Trend trades store `trend_atr`, `sl0` (initial SL, for R) and `stop_at` (since when the current `stop_loss` applies); `update_trend_stops()` (morning scan) first runs `check_all()` with the old stops, then raises stops from CLOSED candles and Telegram tells the user the new SL. `report.ticket_lines` warns when open trades leave too little cash (same no-margin rule as `backtest.portfolio`). Telegram: "✅ Το πήρα" inline button (`took:` callback, in-memory `pending`, lost on restart), `/trades`, `/close ID [PRICE]`, `/cancel ID`, `/mystats`, `/stop SYMBOL [STOP DD/MM]` (shows the trailing-stop calculation step by step via `portfolio.stop_steps`, so the user can do it by hand); job `check_trades` every 10 min replays 15m candles since entry (`tp1_at` so breakeven applies only after TP1), closes hits, **adds realized P&L to `config.yaml` account.balance**, and messages what to change on the platform.
- `autoscan.py` — the Alpaca universe scan (`autoscan.run`, called by `scheduled_scan` only in the real daily run, never `/a` or the silent restart scan): `UNIVERSE` = 99 current S&P 500 members with the highest 63-day median dollar volume (built 2026-10-19 from `data/research/sp500`, no share classes; override with a list in `broker.universe`). One batched `yf.download` (retried for missing symbols — Yahoo sometimes answers "possibly delisted"), weekly bars derived from daily, ONLY closed daily candles, and exactly the backtest's evaluation (`_trend_factors` without news, closed HTF candles, fresh = bias of the last closed bar ≠ previous bar). Validated 2026-10-19: finds 105/106 backtest entries on 6 stocks; residual stop differences came from Yahoo returning slightly different adjusted data between downloads. Same-day signals ordered by score, at most `broker.max_new_per_day`; each opened trade's signal is recorded in the journal (`kind='stock'` — e.g. STX is also a crypto ticker, so always resolve with `.US`) and linked via `my_trades.signal_id`. `data/autoscan.json` remembers the processed bar (no repeat after holidays).
- `broker.py` — automated Alpaca **paper** trading via plain `requests` (no SDK). `open_from_analysis` = market order GTC with OTO stop leg, qty from Alpaca equity × `broker.risk_per_trade_pct` (0.5) / plan risk, capped by `broker.max_position_pct` (10), `max_order_usd` and free cash (cash minus unfilled buy orders); skips if a position/order/open trade exists in the symbol, if `broker.max_positions` (10) is reached, or if `client_order_id tb-SYM-YYYYMMDD` was already used. `health()` = bug circuit breaker run with every sync: day loss > `max_day_loss_pct` (vs `last_equity`), a SHORT position, cost basis > 1.5× the position cap, or more than `max_new_per_day` bot buy orders today → `pause(reason)` (auto_trade off, reason in `data/broker_state.json`, alert; `/auto on` resumes); untracked positions only warn (`once_today`). `snapshot()` stores daily equity in `data/broker_equity.json` (account vs SPY in `/alpaca`, `/week`, dashboard). `compare(t)` replays the linked journal signal (`journal.replay`, unadjusted prices) vs the Alpaca execution in plan-R; `execution_summary()` aggregates it, counting outcome mismatches (closed live, still open/SKIP in the backtest). Recorded in `my_trades` with `broker='alpaca'`, `broker_order`, `filled`. `sync()` (every `check_trades` run and before raising stops): records the fill (`portfolio.set_fill`), closes at once if it opened below the SL (`GAP`), re-creates a GTC stop if none is active, closes the trade from the sell fill when the position is gone (`STOP`/`SL`). Raised trailing stops are pushed with `set_stop` (PATCH, else cancel + new). `/close ID` on a broker trade → `close_position`. Broker trades never touch `config.yaml` balance, are skipped by `portfolio.check_all` and the ticket cash warning, and have separate stats (`portfolio.stats(broker=True)`); `portfolio.plan_r` = R in plan-risk units (like the backtest), `portfolio.history`. Telegram: `/alpaca`, `/auto on|off`, `/history [N]`, `/week` + `weekly_job` (Saturday, 2 h after the morning scan); sync events carry a 📐 backtest comparison line; `selfcheck.patience_note(n)` (loss probability after n trades even if the edge is real, from the honest-test bootstrap) appears in `/week`, selfcheck and the dashboard «Αποτελέσματα» tab. Verified 2026-10-19 against the real paper API: OTO + GTC accepted (with a limit parent), the stop leg is seen by `_stop_orders` (status `held`), PATCH of its stop works, cancel works; a market+GTC parent not yet seen live — `open_from_analysis` retries with `day` on any rejection. Paper account is a 4× margin account: sizing must stay cash-only.
- Telegram bot resilience (2026-10-19, after a startup `TimedOut` crash on a Wi-Fi hiccup): `_request()` = HTTPXRequest with 20 s connect timeout and an `httpx.AsyncHTTPTransport(retries=3)` (connection retries), `run_polling(bootstrap_retries=-1)` (startup waits for the network), and `run_forever()` restarts `main()` 30 s after any unexpected exception. Keep `start_bot.bat` free of non-ASCII text after `chcp 65001` and without `goto` loops: cmd mis-reads UTF-8 multibyte lines (verified: it executed garbage fragments).
- `selfcheck.py` — monthly self-check (`/selfcheck`, job `run_monthly` day 1, `cli.py --selfcheck`): backtests the current rules and a SMALL fixed list of `CANDIDATES` on the watchlist, measures R/year per stock on old and new data, one-account CAGR vs SPY, and live journal results vs backtest. Suggests a change only if a candidate beats the current rules on BOTH old and new data by ≥15% and +0.05 R/yr; the user applies it with the `apply:` inline button (`selfcheck.apply` writes `config.yaml`). History in `data/selfcheck.json`. The watchlist is survivorship-biased (today's winners) — confirm a suggested change with `research/honest_test.py` before trusting it.
- `research/` (not part of the bot): `lab.py` = fast simulator that precomputes the engine's score/levels per bar (cached in `data/research/pre/`, invalidated by a hash of indicators/_trend_factors/levels) and reproduces `backtest.run` trade-for-trade; `port.py` = one-account simulation + SPY / equal-weight benchmarks; `honest_test.py` = point-in-time S&P 500 test (membership from github.com/fja05680/sp500, prices in `data/research/sp500/prices.pkl`, `--update` to refresh). Use these for any new rule idea before touching the engine.
- `strategies.py` — research harness for classic rule-based strategies (`python -m tradebot.strategies 1d`), same fees/R accounting, compared against the bot. None beat it on recent data; use it to test strategies the user brings (add an `entries`/`exit_now` branch).
- `replay.py` — builds a self-contained Plotly.js HTML page (embedded via `st.iframe`) that replays a backtest bar by bar in the browser: play/pause, speed, jump to date/trade, active trade's SL/TP lines and entry `reasons`. Each `Trade` keeps `exit_at`, `exit_price`, `reasons`; `Result.df` holds the candles + EMAs for charts.
- `report.py` (Telegram HTML / plain text), `chart.py` (mplfinance PNG for analyses; `backtest_png` = all trades on price + 90-day zoom + equity, sent by `/backtest`), `journal.py` (SQLite paper-trading log; `evaluate_open` replays 1h candles after each fixed-exit signal: SL before TP1 = -1R, after TP1 the SL moves to entry with half closed, worst case assumed when SL and TP hit in the same candle; trend-exit signals (`trend_atr` column) replay the timeframe's candles from the next open like the backtest, status `STOP`/`SL`, or `SKIP` if it opened beyond the SL — excluded from stats).

## Config & state

- `config.yaml` — account/risk, thresholds, exchange, watchlist, alert interval. It is **re-read on every call** via `load_config()` and **written back** by `save_config()` from Telegram commands (`/watch`, `/balance`, `/risk`) and the dashboard sidebar, so don't cache it.
- `.env` — `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (when set, the bot ignores all other chats), `ALPACA_API_KEY` / `ALPACA_SECRET_KEY` (paper only), `GEMINI_API_KEY` (free tier, a project WITHOUT billing). `config.yaml` `broker:` = `auto_trade`, `max_positions`, `max_order_usd`.
- `data/` — runtime state (journal DB, `selfcheck.json`, `research/` caches ≈1 GB), git-ignored.
